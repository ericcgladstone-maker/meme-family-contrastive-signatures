## §4: D4
- **D4 (cross-new-family duplicates; batch-equivalent by construction).**
  - Every new family that **reaches D4**, i.e. has ≥ MIN_VARIANTS images after D1–D3, contributes its **immutable** post-D3 set P_f. P_f never changes afterwards, whatever the family's later status.
  - **Duplicate relation:** image a ∈ P_f and image b ∈ P_g (f ≠ g) are related if they have identical SHA-256 or a pHash Hamming distance ≤ 6.
  - **Label conflict:** for a pair (f, g), if the images of f related to g exceed 50% of |P_f|, or those of g related to f exceed 50% of |P_g|, **both** f and g are `label_conflict`. Denominators are always the immutable |P|.
  - **Retained set** = P_f minus **every** image of f that is related to any image of any other family that reached D4, including `label_conflict` families. A family whose retained set has fewer than MIN_VARIANTS images is `too_small`.
  - **Recomputation:** after each new family reaches D4, all statuses and retained sets are recomputed **from scratch** over all families that ever reached D4 (`screen_and_retrieve.d4_resolve`). The result never depends on arrival order.
  - **Verified on synthetic data** (`engineering/e3_d4_closure_test.py`):
    - an image shared by A, B and C is removed from all three;
    - identical results across all 120 insertion orders of 5 families;
    - the >50% rule, and the Hamming-6 versus Hamming-7 boundary;
    - the v0.4 mutable-set logic is confirmed to have kept the shared image in C.

## §5: stopping rule
**Stopping rule (dynamic closure), stated literally:**
- **Closure condition:** H ≥ 60 **and** (C = 20 **or** the C-queue is exhausted) **and** H + C ≥ 70, where H and C count families currently `analyzable` after the latest D4 recomputation.
- **Procedure** (the next candidate is always chosen by this rule):
  1. If H < 60, screen the next candidate in the H queue.
  2. Otherwise, if C < 20 and the C-queue is not exhausted, screen the next C-queue candidate.
  3. Otherwise, if H + C < 70, screen the next candidate in the H queue.
  4. Otherwise, stop.
- Because D4 is recomputed after every family, a later family can move an earlier family (H or C) to `too_small` or `label_conflict`. The procedure then re-opens the appropriate queue automatically. H stops as soon as the rule above is satisfied, so it is not driven above 60 except through the H + C ≥ 70 branch.
- **Screening never stops early because results "look stable."** Scoring (§9) begins only after closure.
- **Budget:** 1,500 **unique candidate entries screened across both queues combined**, each counted once and including every exclusion. If closure is not reached within the budget, stop and apply the §11 shortfall rule.
- Verified on synthetic data (T5): a C family knocking an H family below the minimum re-opens H screening, and a token-matching slug reached in the H sequence stays in H.
